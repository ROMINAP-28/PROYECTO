2. INVESTIGACIÓN DE LA CAUSA DEL HUECO DE ARRANQUE (176 s vs 13.8 s)
------------------------------------------------------------------------------
Evidencia en log de arranque previo:
- 12:16:54.933: Initialized JPA EntityManagerFactory for persistence unit 'default'
- 12:19:42.943: WelcomePageHandlerMapping - Adding welcome page: static/index.html
- 12:19:43.663: "Started TravelinkApplication in 176.52 seconds (process running for 13.862)"

Causas Técnicas Identificadas:
1. Métrica de Spring Boot vs Tiempo Real de CPU:
   - "process running for 13.862": El proceso JVM estuvo ejecutándose activamente en CPU solo 13.86 segundos.
   - "Started in 176.52 seconds": Mide la diferencia entre System.currentTimeMillis() y el StartTime reportado por el RuntimeMXBean.
   - En entornos Docker Desktop sobre Windows/WSL2, la pausa de ~162 segundos ocurre durante la fase de espera y sincronización del reloj del hipervisor WSL2 mientras se construía la imagen multi-stage (builder) y se esperaba el healthcheck del contenedor MySQL (start_period: 15s + retries).
2. Verificación Dinámica de Índices en TravelinkApplication:
   - La clase CommandLineRunner ejecuta 10 sentencias CREATE INDEX de manera síncrona. Si bien en una base vacía tarda ~30 ms, si la conexión aún está negociando el handshake TLS/characterEncoding con MySQL o si existen bloqueos de tabla por scripts de inicialización /docker-entrypoint-initdb.d/, la verificación de índices puede retener el hilo 'main'.
3. Escaneo de Rutas Estáticas Inexistentes:
   - spring.web.resources.static-locations incluía rutas inexistentes como "file:./backend/resources/static/". Spring escanea múltiples ubicaciones en disco antes de mapear la WelcomePage.

Acción de Mitigación:
- Desacoplar rutas inexistentes.
- Ajustar timeouts y optimizar el healthcheck mediante Spring Boot Actuator nativo (/actuator/health).
