## 1. Descripción de la Vulnerabilidad
En el método `verificarContrasena(String rawPassword, String encodedPassword)` de la clase `UsuarioServicioImpl`, existe una bifurcación de respaldo para desarrollo que valida la autenticación de **cualquier usuario del sistema** si la contraseña ingresada coincide con valores predefinidos (`"123456"`, `"12345678"`, `"pass123"`, `"admin"`, `"admin123"`), eludiendo por completo la verificación criptográfica contra el hash BCrypt almacenado en la base de datos.

## 2. Evidencia en Código Fuente
Extracto literal de [`UsuarioServicioImpl.java`](file:///d:/ProyectosU/PROYECTO/Springboot/src/com/travelink/servicio/impl/UsuarioServicioImpl.java#L109-L134):

```java
    @Override
    public boolean verificarContrasena(String rawPassword, String encodedPassword) {
        if (rawPassword == null || encodedPassword == null) return false;
        String rawTrimmed = rawPassword.trim();
        String encTrimmed = encodedPassword.trim();

        if (encTrimmed.startsWith("$2")) {
            if (passwordEncoder.matches(rawPassword, encTrimmed) || passwordEncoder.matches(rawTrimmed, encTrimmed)) {
                return true;
            }
        } else if (encTrimmed.equals(rawPassword) || encTrimmed.equalsIgnoreCase(rawTrimmed)) {
            return true;
        }

        // Respaldo para entorno de desarrollo y pruebas locales
        if ("123456".equals(rawTrimmed) || "12345678".equals(rawTrimmed) || "pass123".equals(rawTrimmed)
                || "admin".equalsIgnoreCase(rawTrimmed) || "admin123".equalsIgnoreCase(rawTrimmed)) {
            return true;
        }

        return false;
    }
```

## 3. Causa Raíz
Lógica de depuración ("Respaldo para entorno de desarrollo y pruebas locales") dejada activa en el servicio de producción. Esta condición permite a cualquier atacante iniciar sesión en la cuenta de **cualquier usuario legítimo** (incluyendo administradores) conociendo únicamente su dirección de correo electrónico e ingresando cualquiera de las cinco contraseñas débiles hardcodeadas.

## 4. Impacto
- **Confidencialidad:** Total (Acceso a paneles administrativos y datos personales de usuarios).
- **Integridad:** Total (Modificación no autorizada de reservas, comisiones y catálogos de tours).
- **Disponibilidad:** Alta (Capacidad de deshabilitar cuentas y cancelar transacciones).

## 5. Recomendación de Mitigación
Eliminar de inmediato el bloque de bypass hardcodeado y delegar la validación al `PasswordEncoder` estándar de Spring Security:

```java
@Override
public boolean verificarPassword(Usuario usuario, String rawPassword) {
    if (usuario == null || rawPassword == null) {
        return false;
    }
    String storedHash = usuario.getPasswordHash();
    if (storedHash == null || !storedHash.startsWith("$2a$") && !storedHash.startsWith("$2b$")) {
        return false;
    }
    return passwordEncoder.matches(rawPassword, storedHash);
}
```
