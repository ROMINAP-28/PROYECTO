## 1. Descripción de la Vulnerabilidad
El script SQL oficial de aprovisionamiento de datos iniciales inserta la cuenta del usuario administrador global (`admin`, correo `admin@travelink.pe`) almacenando la cadena literal `'123456'` en la columna `contrasena`, en lugar de un hash seguro generado con una función criptográfica robusta como BCrypt. En conjunto con la lógica de verificación en `UsuarioServicioImpl.java` (que acepta contraseñas sin hash mediante comparación directa), cualquier atacante puede iniciar sesión como superadministrador con la credencial pública por defecto `admin / 123456`.

## 2. Evidencia en Código Fuente
Extracto literal de [`sql/datos_minimos.sql`](file:///d:/ProyectosU/PROYECTO/sql/datos_minimos.sql#L18-L26):

```sql
-- 2. Persona y Usuario Administrador Inicial
INSERT INTO Persona (idPersona, nombre, apellidoPaterno, apellidoMaterno, nroDocumento, telefono, email) VALUES
(1, 'Administrador', 'Travelink', 'Sistema', '00000001', '999888777', 'admin@travelink.pe')
ON DUPLICATE KEY UPDATE nombre = VALUES(nombre), email = VALUES(email);

INSERT INTO Usuario (idUsuario, idPersona, idRol, nombreUsuario, contrasena, estado) VALUES
(1, 1, 3, 'admin', '123456', 'ACTIVO')
ON DUPLICATE KEY UPDATE idRol = 3, contrasena = VALUES(contrasena), estado = 'ACTIVO';
```

## 3. Causa Raíz
Ausencia de políticas criptográficas forzadas en los scripts DML de inicialización y falta de sincronización con el componente `BCryptPasswordEncoder` configurado en `SecurityConfig`.

## 4. Impacto
- Exposición de credenciales privilegiadas en volcados de base de datos, repositorios de código y respaldos.
- Posibilidad de inicio de sesión administrativo directo si la lógica del controlador acepta comparación en texto plano o si se explota en conjunto con `H-01`.

## 5. Recomendación de Mitigación
Reemplazar la cadena en texto plano por un hash BCrypt con costo computacional mínimo 10 generado dinámicamente o precalculado:

```sql
-- Hash BCrypt para 'Admin#Seguro2026' con factor de costo 10
INSERT INTO Usuario (nombre, correo, clave, idRol)
SELECT 'Administrador', 'admin@travelink.com', '$2a$10$q03U76nL7QjVl/e.1jZ/jOCQ2l86m7VzQ4XQ1H8jC7WpA6V8z.W2e', idRol
FROM Rol WHERE nombre = 'ADMINISTRADOR'
ON DUPLICATE KEY UPDATE clave = VALUES(clave);
```
