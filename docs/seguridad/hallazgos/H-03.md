## 1. Descripción de la Vulnerabilidad
El endpoint `GET /api/obtener_reservas` está configurado como público (`permitAll()`) en `SecurityConfig.java`. Permite consultar el historial completo de reservas de cualquier usuario simplemente proporcionando el parámetro `idUsuario` o `correo` en la URL. La respuesta incluye nombres de pasajeros, documentos de identidad (DNI), teléfonos, montos pagados y datos de tarjetas financieras (`marcaTarjeta`, `ultimosDigitos`).

## 3. Evidencia Dinámica (Fuzzing / PoC)
La herramienta de fuzzing registró código HTTP 200 sin credenciales:
```json
{
  "input": "obtener_reservas",
  "url": "http://127.0.0.1:8080/api/obtener_reservas",
  "status": 200,
  "length": 34
}
```
Al invocar `GET /api/obtener_reservas?idUsuario=100`, un atacante no autenticado obtiene la reserva `#500` con el documento del pasajero `10000001` y la tarjeta terminada en `1111` pertenecientes al seed sintético.

## 4. Causa Raíz
Delegación del control de acceso a parámetros controlados por el cliente (Client-Controlled Object References) en lugar de extraer de forma obligatoria la identidad del sujeto desde el `SecurityContext` o sesión HTTP criptográfica.

## 5. Impacto
- Exposición masiva de datos personales regulados por normativas de privacidad (GDPR / Ley de Protección de Datos Personales).
- Cancelación arbitraria de reservas comerciales legítimas por parte de terceros malintencionados.

## 6. Recomendación de Mitigación
1. Proteger el endpoint en `SecurityConfig`: `.requestMatchers("/api/obtener_reservas").authenticated()`.
2. Extraer el identificador de usuario exclusivamente desde el contexto de seguridad autenticado:

```java
Integer currentUserId = SecurityUtils.getAuthenticatedIdUsuario()
    .orElseThrow(() -> new ResponseStatusException(HttpStatus.UNAUTHORIZED, "Sesión requerida"));

// Ignorar cualquier parámetro idUsuario proveniente del query string
List<ReservaDTO> reservas = reservaServicio.obtenerPorUsuario(currentUserId);
```
