## 1. Descripción de la Vulnerabilidad
En el bean `corsConfigurationSource()` de `SecurityConfig.java`, se configura el patrón comodín abierto `setAllowedOriginPatterns(List.of("*"))` en combinación directa con la propiedad `setAllowCredentials(true)` y registro global para todas las rutas (`/**`). Esto permite que un sitio web malicioso ejecute peticiones autenticadas cross-origin contra la API y lea las respuestas utilizando las cookies o cabeceras de sesión de la víctima.

## 2. Evidencia en Código Fuente
Extracto literal de [`SecurityConfig.java`](file:///d:/ProyectosU/PROYECTO/Springboot/src/com/travelink/config/SecurityConfig.java#L267-L278):

```java
    @Bean
    public CorsConfigurationSource corsConfigurationSource() {
        CorsConfiguration configuration = new CorsConfiguration();
        configuration.setAllowedOriginPatterns(List.of("*"));
        configuration.setAllowedMethods(Arrays.asList("GET", "POST", "PUT", "DELETE", "OPTIONS", "PATCH"));
        configuration.setAllowedHeaders(Arrays.asList("Authorization", "Content-Type", "X-Requested-With", "Accept", "X-XSRF-TOKEN"));
        configuration.setExposedHeaders(Arrays.asList("Authorization", "X-XSRF-TOKEN"));
        configuration.setAllowCredentials(true);

        UrlBasedCorsConfigurationSource source = new UrlBasedCorsConfigurationSource();
        source.registerCorsConfiguration("/**", configuration);
        return source;
    }
```

### Evidencia Dinámica Adicional (Nikto v2.1.6 — `alpine/nikto`)
Extracto del escaneo ejecutado contra `http://host.docker.internal:8080` (`docs/seguridad/evidencias/nikto/nikto-output.txt`):

```text
+ Retrieved access-control-allow-origin header: nikto.example.com
```

Confirmación dinámica de que el backend refleja un origen externo arbitrario (`nikto.example.com`) en la cabecera `Access-Control-Allow-Origin` producto de `setAllowedOriginPatterns(List.of("*"))`.

El valor 'nikto.example.com' corresponde al Origin de prueba que Nikto envió en su petición; el servidor lo reflejó automáticamente, confirmando que acepta y refleja cualquier origen arbitrario (ver `PoC-04-CORS.md` con `Origin: http://sitio-malicioso.local` para el mismo comportamiento).

## 3. Causa Raíz
Uso de comodines `*` en `allowedOriginPatterns` combinado con `allowCredentials(true)` para simplificar el desarrollo local, contraviniendo las directivas de seguridad del estándar W3C CORS y de Spring Security.

## 4. Impacto
- Exfiltración de datos sensibles de usuarios autenticados mediante scripts ejecutados en dominios maliciosos (Cross-Site Script Inclusion / CSRF con lectura de respuesta).
- Secuestro de sesión y robo de información personal mediante técnicas de client-side side-channel.

## 5. Recomendación de Mitigación
Restringir los orígenes permitidos estrictamente a la lista blanca de dominios de producción y pruebas autorizados:

```java
@Bean
public CorsConfigurationSource corsConfigurationSource() {
    CorsConfiguration configuration = new CorsConfiguration();
    configuration.setAllowedOrigins(List.of(
        "https://www.travelink.com",
        "https://app.travelink.com"
    ));
    configuration.setAllowedMethods(List.of("GET", "POST", "PUT", "DELETE"));
    configuration.setAllowedHeaders(List.of("Authorization", "Content-Type", "X-XSRF-TOKEN"));
    configuration.setAllowCredentials(true);
    configuration.setMaxAge(3600L);
    
    UrlBasedCorsConfigurationSource source = new UrlBasedCorsConfigurationSource();
    source.registerCorsConfiguration("/api/**", configuration);
    return source;
}
```
