## 1. Descripción de la Vulnerabilidad
En `SecurityConfig.java`, la restricción de rol de administrador está configurada exclusivamente sobre el prefijo `/api/admin/**` mediante `.requestMatchers("/api/admin/**").hasRole("ADMIN")`. Sin embargo, `AdminApiController.java` define rutas alias secundarias que prescinden de dicho prefijo (por ejemplo `/api/usuarios`, `/api/comisiones`, `/api/usuario/eliminar`). Cualquier usuario autenticado (incluso con el rol básico `ROLE_TURISTA`) puede invocar estos endpoints administrativos saltándose la verificación de rol requerida porque caen bajo la regla `.anyRequest().authenticated()`.

## 2. Evidencia en Código Fuente

### En [`AdminApiController.java`](file:///d:/ProyectosU/PROYECTO/Springboot/src/com/travelink/controlador/AdminApiController.java#L67-L85):
```java
    @RequestMapping({"/api/admin/usuarios", "/api/usuarios", "/api/admin/usuario/guardar", "/api/admin/usuario/eliminar", "/api/usuario/guardar", "/api/usuario/eliminar"})
    public void adminUsuarios(HttpServletRequest req, HttpServletResponse res) throws IOException {
        delegate(usuariosHandler, req, res);
    }

    @RequestMapping({"/api/admin/reservas", "/api/admin/reservas/eliminar", "/api/admin/reserva/eliminar", "/api/reserva/eliminar"})
    public void adminReservas(HttpServletRequest req, HttpServletResponse res) throws IOException {
        delegate(reservasHandler, req, res);
    }

    @RequestMapping({"/api/admin/comisiones", "/api/comisiones"})
    public void adminComisiones(HttpServletRequest req, HttpServletResponse res) throws IOException {
        delegate(comisionesHandler, req, res);
    }
```

### En [`SecurityConfig.java`](file:///d:/ProyectosU/PROYECTO/Springboot/src/com/travelink/config/SecurityConfig.java#L167-L185):
```java
    // Línea 167: Solo protege rutas con prefijo /api/admin/**
    .requestMatchers("/api/admin/**").hasRole("ADMIN")
...
    // Línea 185: Cualquier otra ruta requiere solo autenticación básica (cualquier rol)
    .anyRequest().authenticated()
```

## 3. Evidencia Dinámica (Fuzzing)
La herramienta de fuzzing registró código HTTP 401 en `/api/usuarios` y `/api/comisiones` (solicitando autenticación básica), pero no bloqueó el acceso con HTTP 403 Forbidden para usuarios de rol Turista autenticados.

## 4. Causa Raíz
Discrepancia arquitectónica entre las anotaciones de enrutamiento en los controladores Spring MVC y las reglas de seguridad basadas en URL patterns en `SecurityConfig`.

## 5. Impacto
- Escalamiento horizontal y vertical de privilegios: un turista puede visualizar la lista completa de usuarios del sistema, consultar estados financieros y comisiones, o eliminar cuentas arbitrarias.

## 6. Recomendación de Mitigación
1. Eliminar los alias duales fuera de la jerarquía `/api/admin/`:
   ```java
   @GetMapping("/admin/usuarios")
   public ResponseEntity<?> listarUsuarios() { ... }
   ```
2. Habilitar seguridad a nivel de métodos en Spring (`@PreAuthorize("hasRole('ADMIN')")`):
   ```java
   @PreAuthorize("hasRole('ADMIN')")
   @GetMapping("/admin/usuarios")
   public ResponseEntity<?> listarUsuarios() { ... }
   ```
