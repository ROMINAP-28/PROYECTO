## 1. Descripción de la Vulnerabilidad
En `SecurityConfig.java`, la restricción de rol de administrador está configurada exclusivamente sobre el prefijo `/api/admin/**` mediante `.requestMatchers("/api/admin/**").hasRole("ADMIN")`. Sin embargo, `AdminApiController.java` define rutas alias secundarias que prescinden de dicho prefijo (por ejemplo `/api/usuarios`, `/api/comisiones`, `/api/usuario/eliminar`). Cualquier usuario autenticado (incluso con el rol básico `ROLE_TURISTA`) puede invocar estos endpoints administrativos saltándose la verificación de rol requerida.

## 2. Evidencia en Código Fuente

### En `SecurityConfig.java`:
```java
// Solo protege rutas que comiencen exactamente con /api/admin/
.requestMatchers("/api/admin/**").hasRole("ADMIN")
// Las rutas restantes /api/** solo exigen estar autenticado:
.requestMatchers("/api/**").authenticated()
```

### En `AdminApiController.java`:
```java
// Mapeos duales que eluden la regla hasRole("ADMIN"):
@GetMapping({"/admin/usuarios", "/usuarios"}) // Accesible en /api/usuarios para cualquier usuario autenticado
public ResponseEntity<?> listarUsuarios() { ... }

@GetMapping({"/admin/comisiones", "/comisiones"}) // Accesible en /api/comisiones
public ResponseEntity<?> verComisiones() { ... }

@DeleteMapping({"/admin/usuario/eliminar", "/usuario/eliminar"}) // Eliminación de usuarios sin rol ADMIN
public ResponseEntity<?> eliminarUsuario(@RequestParam Integer id) { ... }
```

## 3. Evidencia Dinámica (Fuzzing)
La herramienta de fuzzing registró código HTTP 401 en `/api/usuarios` y `/api/comisiones` (solicitando autenticación básica), pero no bloqueó el acceso con HTTP 403 Forbidden para usuarios de rol Turista autenticados.

## 4. Causa Raíz
Discrepancia arquitectónica entre las anotaciones de enrutamiento en los controladores Spring MVC y las reglas de seguridad basadas en URL patterns en `SecurityConfig`.

## 5. Impacto
- Escalamiento horizontal y vertical de privilegios: un turista puede visualizar la lista completa de usuarios del sistema, consultar estados financieros y comisiones, o eliminar cuentas arbitrarias.

## 6. Recomendación de Mitigación
1. Eliminar los alias duales fuera de la jerarquía `/api/admin/`:
   ```java
   @GetMapping("/admin/usuarios")
   public ResponseEntity<?> listarUsuarios() { ... }
   ```
2. Habilitar seguridad a nivel de métodos en Spring (`@PreAuthorize("hasRole('ADMIN')")`):
   ```java
   @PreAuthorize("hasRole('ADMIN')")
   @GetMapping("/admin/usuarios")
   public ResponseEntity<?> listarUsuarios() { ... }
   ```
